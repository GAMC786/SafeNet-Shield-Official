---
name: Tailscale hosted control plane
description: Architecture and evidence boundaries for SafeNet's Tailscale integration.
---

SafeNet integrates with Tailscale's hosted control plane using a server-side OAuth client with the read-only `devices:core:read` permission. Exchange client credentials by POSTing `client_id` and `client_secret` as form fields to `/api/v2/oauth/token`; the OAuth client's configured permissions determine token scope, so don't send credentials with HTTP Basic auth or request scope dynamically. The official Tailscale client repository is not a self-hostable control-plane deployment. SafeNet can report API reachability and device control-plane status, but neither proves that an Android device is routing traffic through Tailscale.

The official Android client is a full app, not a drop-in Android SDK or published Maven dependency. Its Gradle build consumes a locally generated `libtailscale.aar` built from Go with gomobile, and its Kotlin service implements Tailscale's `VpnService` and local control API. In-app connection controls therefore require adopting and maintaining the native engine/service integration; hosted API calls cannot connect or disconnect the phone.

**Why:** Tailscale's documented token request uses form fields, and a healthy dashboard or API can coexist with a disconnected client or unusable peer route; claiming mesh connectivity from control-plane status alone would be misleading. The Android VPN engine also has no supported third-party SDK boundary, so a UI-only API integration cannot provide actual device traffic routing.

**How to apply:** Keep credentials server-side and narrowly scoped. Treat physical Android route plus an approved-peer probe as separate evidence, and report missing device or runner prerequisites as blocked rather than as a pass. After Android VPN consent/start, the local engine may publish its sign-in URL asynchronously; poll briefly before giving up and show a retryable error if no URL arrives. Route Quick Settings actions through the app's existing EULA, App Lock, and VPN-consent path rather than starting the engine directly from the tile. The hosted control-plane health route is separate and must not gate native sign-in. Before adding SafeNet-owned Tailscale VPN controls, pin and build the upstream Android engine source, implement its VPN service lifecycle and consent, and account for the Go/gomobile toolchain in release CI.
